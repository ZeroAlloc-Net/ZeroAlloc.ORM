# ZAO065 — Decimal output parameter has no Scale

**Severity:** Warning
**Category:** ZeroAlloc.ORM

## Trigger

Fires on a `[StoredProcedure]` output or input-output parameter of type
`decimal` that has no `[Param(Scale = ...)]`.

The generator sets `DbType = Decimal` on the output parameter but no
precision or scale, because it cannot know what the procedure declares, and a
guessed scale is as wrong as a missing one. Providers differ in what they do
next:

| Provider | Output `decimal` without a scale |
|----------|----------------------------------|
| SQL Server (Microsoft.Data.SqlClient 7.1) | Declared as scale 0. The value the procedure assigns is **rounded to a whole number**, with no error: `1234.5678` comes back as `1235`. `Precision` alone does not help; `Scale` does. |
| PostgreSQL (Npgsql 10) | Returned exactly. The `CALL` sends `NULL` for an `OUT` argument and the value comes back as `numeric`. |

## Why a warning

On SQL Server the value is lost without an error, and the generator cannot
see which provider runs the procedure. A warning shows in `dotnet build`
output and fails a warnings-as-errors build, so the rounding is caught before
it ships.

## Fix

Set `Precision` and `Scale` to match the procedure's declaration:

```csharp
// CREATE PROCEDURE dbo.usp_Quote @total DECIMAL(18,4) OUTPUT AS ...
[StoredProcedure("dbo.usp_Quote")]
public partial Task<(int Status, decimal Total)> QuoteAsync(
    int status,
    [Param(Precision = 18, Scale = 4)] decimal total,
    CancellationToken ct);
```

If the procedure only ever runs on PostgreSQL, the value comes back exact
and the diagnostic does not apply. Turn it off for that project in
`.editorconfig`:

```ini
dotnet_diagnostic.ZAO065.severity = none
```

## Not triggered when

* The parameter is an input parameter. SqlClient derives an input decimal's
  precision and scale from the value.
* `[Param(Scale = ...)]` is set, including `Scale = 0`.
* `[Param(DbType = ...)]` overrides the type with something other than
  `DbType.Decimal`.
