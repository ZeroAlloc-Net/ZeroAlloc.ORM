# ZAO066 — [Param] member does not apply to this parameter

**Severity:** Error
**Category:** ZeroAlloc.ORM

## Trigger

Fires when a `[Param]` member is written where the generator cannot honour
it, so it would otherwise be dropped without a word or fail at run time:

* **Any member on a `CancellationToken`, transaction or BulkInsert collection
  parameter.** None of them binds a `DbParameter` of its own, so `Name`,
  `DbType`, `Size`, `Precision`, `Scale` and `Direction` have nothing to apply
  to.
* **`DbType`, `Size`, `Precision`, `Scale` or `Direction` on a composite
  parameter.** A composite such as `Money(decimal Amount, string Currency)`
  binds as one `DbParameter` per field, `total_Amount` and `total_Currency`, so
  one set of facets cannot describe it. `Name` on a composite is reported by
  [ZAO063](ZAO063.md) instead.
* **`Size` below `-1`.** Every provider rejects it when the parameter is
  bound.
* **`Direction = Output`, `InputOutput` or `ReturnValue` on a parameter that
  nothing reads back.** Output values are read back only for a
  `[StoredProcedure]` parameter whose name matches a field of the returned
  named tuple. Anywhere else the value would be lost.
* **`Direction = Input` on a parameter that a tuple field reads back.** A
  tuple-matched parameter is read back after the call; `Output`, the default,
  `InputOutput` and `ReturnValue` are supported. `ReturnValue` has its own
  checks, [ZAO067](ZAO067.md) and [ZAO068](ZAO068.md).
* **`Size = 0` on a `string` or binary output or input-output parameter.**
  SqlClient throws "the Size property has an invalid size of 0" before it
  sends the call. Leave `Size` unset for the default of `-1`, which is `MAX`,
  or write the length the procedure declares.
* **A fixed-length `DbType`, `StringFixedLength` or `AnsiStringFixedLength`,
  on an output or input-output parameter without a `Size`, or with
  `Size = 0`.** SqlClient rejects the size of 0 in the same way. The generator
  gives it no default: SqlClient accepts `-1`, but that declares a `MAX` type,
  not the fixed length you chose. Write the length the procedure declares:
  `NCHAR(10)` is `Size = 10`.

`Size`, `Precision`, `Scale` and `Direction` are new in 2.0. `Name` and
`DbType` existed in 1.x but were not checked: a `Name` on a
`CancellationToken`, or a `DbType` anywhere, was dropped without a word. Code
that writes one of those where it cannot apply now fails to build with ZAO066.

## Fix

```csharp
// Fires ZAO066: `extra` matches no tuple field, so its value is never read.
[StoredProcedure("usp_Allocate")]
public partial Task<(int NewOrderId, int Status)> AllocateAsync(
    int newOrderId,
    int status,
    [Param(Direction = ParameterDirection.Output)] int extra,
    CancellationToken ct);

// Fix: add the tuple field that reads it back.
[StoredProcedure("usp_Allocate")]
public partial Task<(int NewOrderId, int Status, int Extra)> AllocateAsync(
    int newOrderId,
    int status,
    int extra,
    CancellationToken ct);
```

For a composite parameter, drop the facets. Each field binds with the type
the provider infers from its value. On a `CancellationToken`, transaction or
BulkInsert collection parameter, drop the `[Param]` attribute.

```csharp
// Fires ZAO066: NCHAR(10) needs its length.
[StoredProcedure("usp_Code")]
public partial Task<(int Id, string Code)> CodeAsync(
    int id,
    [Param(DbType = DbType.StringFixedLength)] string code,
    CancellationToken ct);

// Fix: give the declared length.
[StoredProcedure("usp_Code")]
public partial Task<(int Id, string Code)> CodeAsync(
    int id,
    [Param(DbType = DbType.StringFixedLength, Size = 10)] string code,
    CancellationToken ct);
```
