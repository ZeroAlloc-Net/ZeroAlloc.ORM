# ZAO107 — Unsupported LINQ projection

**Severity:** Error
**Category:** ZeroAlloc.ORM

## Trigger

Fires when a `[LinqQuery]` chain's `Select` is not one the translator reads. Supported is `Select(t => new Row(...))`, where:

- `Row` is a positional record, constructed through its widest public constructor, the one rows are read with;
- each argument is a mapped column, a companion parameter, or a literal;
- no object initializer is used;
- no constructor parameter of `Row` reads several columns, as a composite or a `[Materialize]` factory type does;
- no argument is a whole object, such as an owned `r.Repository`: project the columns it holds;
- a member of an optional owned object, such as `r.Outcome!.HasFailedValidation` for `AnalysisOutcome? Outcome`, goes to a parameter that takes a null, such as `bool?`. It is NULL when the request has no outcome.

After a `GroupBy`, `Select` is required, and each argument is `g.Key`, a member of it, a group aggregate, a companion parameter or a literal. After a `Join`, an argument may also be a member of a joined source, such as `x.Task.Title`. A `GroupBy` without a `Select` fires ZAO107.

Arguments may be named and in any order; each goes to the parameter it binds. A chain without `Select`, and a projection to one value such as `Select(t => t.Title)`, also fire it. It is reported at the projection or the offending argument.

A scalar terminal such as `Sum` or `Average` returns its value and needs no `Select`.

## Fix

Project into a positional record that holds the columns you need.

## Example

```csharp
// Fires ZAO107 — a single-column projection:
private static IQuery<string> TitlesQuery() =>
    Sql.Table<TaskEntity>().Select(t => t.Title);
```

Fix by projecting a record:

```csharp
public sealed record TitleRow(string Title);

private static IQuery<TitleRow> TitlesQuery() =>
    Sql.Table<TaskEntity>().Select(t => new TitleRow(t.Title));
```
