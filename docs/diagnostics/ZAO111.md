# ZAO111 — LINQ enum parameter compared with or set into differently stored columns

**Severity:** Error
**Category:** ZeroAlloc.ORM

## Trigger

Fires when a `[LinqQuery]` or `[LinqCommand]` companion compares one enum parameter with, or sets it into, two kinds of column:

- a column whose `[ColumnMap]` sets `EnumAsString = true`, which stores the member name;
- a column that stores the enum's integer, the default.

An enum parameter binds one value. Compared with or set into an `EnumAsString` column it binds as its member name, the way a `[StoreAsString]` enum does, with `DbType.String`; compared with or set into an integer column it binds as its integer. It cannot do both, so the query is rejected. An `ExecuteUpdate` setter's target column counts as a comparison does: `SetProperty(t => t.Kind, kind)` together with `Where(t => t.PreviousKind == kind)` fires it.

An enum type marked `[StoreAsString]` is stored by name everywhere, whatever the map says, so its parameters never trigger ZAO111.

It is reported at the parameter in the comparison or setter that disagrees with the first one. An update's setters are read before its conditions.

## Fix

Store the enum the same way in both columns, or pass two parameters, one for each column.

## Example

```csharp
public enum WorkKind { Bug, Feature }

[TableMap(typeof(TaskEntity), "Tasks")]
[ColumnMap(nameof(TaskEntity.Kind), EnumAsString = true)]   // "Kind" holds 'Bug' or 'Feature'
internal static class TaskMap;                              // "PreviousKind" holds 0 or 1

// Fires ZAO111 on the second `kind`:
private static IQuery<TaskSummary> FindQuery(WorkKind kind) =>
    Sql.Table<TaskEntity>()
        .Where(t => t.Kind == kind || t.PreviousKind == kind)
        .Select(t => new TaskSummary(t.Id, t.Title));
```

Fix:

```csharp
private static IQuery<TaskSummary> FindQuery(WorkKind kind, WorkKind previous) =>
    Sql.Table<TaskEntity>()
        .Where(t => t.Kind == kind || t.PreviousKind == previous)
        .Select(t => new TaskSummary(t.Id, t.Title));
```

A setter fires it the same way:

```csharp
// Fires ZAO111 on `kind` in the Where — the setter bound it by name for "Kind" first:
private static int ReclassifyQuery(Guid id, WorkKind kind) =>
    Sql.Table<TaskEntity>()
        .Where(t => t.Id == id && t.PreviousKind == kind)
        .ExecuteUpdate(set => set.SetProperty(t => t.Kind, kind));
```

Fix by passing a second parameter for the integer column, as above.
