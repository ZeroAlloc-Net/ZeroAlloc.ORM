# ZAO102 — Unsupported LINQ construct

**Severity:** Error
**Category:** ZeroAlloc.ORM

## Trigger

Fires on a construct in a `[LinqQuery]` or `[LinqCommand]` chain that the translator does not turn into SQL, such as an operator from another library, a method of your own, or an operator after `Select`. A chain is translated in full at build time or not at all, so nothing is left to run in memory. The message names the construct, and it is reported at it.

SQL filters, orders, pages and then projects, so the chain does too. `Where` and the orderings may come in any order among themselves, but before `Skip` and `Take`:

- `Where` and `WhereIf`;
- `OrderBy` or `OrderByDescending` once, then any `ThenBy` and `ThenByDescending`. Each key is a mapped column. An enum stored by name, through `[StoreAsString]` or a map that sets `EnumAsString`, orders by its member names, as text;
- `Skip`, then `Take`, each at most once. The count is a companion parameter, where a negative value counts as 0 as in LINQ, or a non-negative `int` literal;
- `Select`;
- `Count()`, `LongCount()` or `Any()`, which end the chain. They may follow `Select`, whose projection they drop;
- `Sum`, `Min`, `Max` and `Average` over a selector, which also end the chain;
- `GroupBy` before `OrderBy`, with a key that is a mapped column, its `.Date`, or an anonymous type of those, ending in `Select` over `g.Key` and the group aggregates `Count`, `LongCount`, `Sum`, `Min`, `Max` and `Average`;
- `Join` of `Sql.Table<T>()`, optionally with `Where`, on a single mapped column on each side, with a result selector that is an anonymous type of range variables or members carried over from an earlier join.
- `ForUpdate()`, `ForUpdateSkipLocked()` or `ForUpdateNoWait()` once, anywhere before `Select`. It renders last, after `LIMIT` and `OFFSET`, and on a chain with a `Join` it locks the rows of every joined table.

So it also fires on `Where` or an ordering after `Skip` or `Take`, which would apply to the page alone; on a second `OrderBy`, where `ThenBy` adds a key; on `Take` before `Skip`; on any operator after a terminal; and on an ordering key or a count of another form.

Inside `Where` and `WhereIf` it also fires on a predicate form the translator does not know. The supported forms are:

- `==`, `!=`, `<`, `<=`, `>` and `>=` between columns, companion parameters and constants, and `== null` / `!= null`;
- `p.HasValue` and `!p.HasValue` on a nullable companion parameter, which read as `p != null` and `p == null`. Any other member of a parameter, such as `p.Value`, is reported: compare the parameter itself;
- `&&`, `||` and `!`, and a `bool` column on its own;
- `string.Equals(a, b)`, with or without `StringComparison.Ordinal`;
- `Contains`, `StartsWith` and `EndsWith` on a string column, with or without `StringComparison.Ordinal`, matched literally;
- `Sql.ILike(column, pattern)`;
- `Contains` on an array parameter: `T[]`, `List<T>` or `IReadOnlyList<T>` of `string`, `int`, `long`, `float`, `double` or `Guid`;
- `Contains` on a query, `Sql.Table<P>()...Select(p => p.Col).Contains(value)`, and its `!`: an `IN` or `NOT IN` subquery;
- `Sql.Row(t.A, t.B) > Sql.Row(p, q)`, with `<`, `<=`, `>` or `>=` and two or three items, for keyset paging. Each pair is a column and a companion parameter or a non-null constant, in either order. An item whose type can be null, such as a `DateTimeOffset?` column or parameter, is reported: a NULL makes the whole row comparison NULL.

Arithmetic, other methods, other `StringComparison` values, and `<`, `<=`, `>` or `>=` on an enum stored by name are reported, including inside `Sql.Row`. An enum stored by name orders by its names in SQL, not by its values.

The aggregate and join operators report as well when:

- `Min` or `Max` is taken over a `bool`, a `Guid` or an enum stored by name: PostgreSQL has no such aggregate, or it would compare the names;
- a `GroupBy` has any other key, such as `t.Order + 1`, is followed by `Where` (the `HAVING` form), is counted with `Count()`, `LongCount()` or `Any()`, or comes after `OrderBy`, `Skip`, `Take` or another `GroupBy`;
- a `Select` after `GroupBy` reads the group other than through `g.Key`, its members and the group aggregates, as in `g.Count() + 1`;
- a `Join` uses a composite key, a computed member in its result selector, an inner side other than `Sql.Table<T>()` with `Where`, or comes after `GroupBy`, `Select`, `Skip`, `Take` or `OrderBy`. There is no left-join operator yet;
- `.Value` is read from a nullable value-object column: a `Nullable<TValueObject>`, or a value object of reference type annotated `?`. Code without nullable annotations cannot be checked, so there a reference-type member counts as not null and its `.Value` reads the column.

A row lock reports as well when it comes with `GroupBy`, `Count()`, `LongCount()`, `Any()`, `Sum`, `Min`, `Max` or `Average`, in either order, which PostgreSQL rejects with `FOR UPDATE`; when it is a second lock in the chain; when it is in the source of a query `Contains`; and in a `[LinqCommand]` chain, where only `Where` and `WhereIf` come before the write.

A `[LinqCommand]` chain is `Sql.Table<T>()`, then `Where` and `WhereIf`, then `ExecuteDelete()` or `ExecuteUpdate(...)`. Any other operator before the write reports at that operator. Inside `ExecuteUpdate` it reports:

- an `ExecuteUpdate` without a `SetProperty`;
- a setter target that is a whole owned object, a column an earlier `SetProperty` sets already, or `xmin`;
- a setter target whose type is a conversion of the column's, such as `(int?)null` or an `int?` or `long` parameter set into an `int` column;
- a setter value other than a companion parameter, a constant, `null`, a column of the row, or `+`, `-` and `*` over those, with `int`, `long`, `decimal`, `double` or `float` operands. `/`, a method call or a cast reports;
- an enum column set from a column that stores the enum the other way;
- a `[Json]` column set from anything other than a parameter, a constant, `null` or another `[Json]` column.

Arithmetic in a condition reports as in a query: it is allowed in setter values only.

A companion parameter binds one way for the whole method, so in a `[LinqQuery]` or a `[LinqCommand]` it also reports when it meets two store types:

- a parameter compared with or set into a jsonb column, which binds as `jsonb`, that also meets a text column, sits in another form such as `LIKE`, or is set into a column that is not jsonb;
- a `DateTime` parameter compared with or set into a column its map declares `DateTimeStorage.Timestamp` and one it declares `DateTimeStorage.TimestampTz`, in one statement or in two of a tuple. A column whose storage is `Default` takes either type. See [DateTime parameters](../cookbook/linq.md#datetime-parameters).

PostgreSQL's `xmin`, through `Sql.Xmin(r)` or a `uint` property the map maps to `xmin`, is a transaction id, compared only for equality. It is read in a projection, into a `uint` parameter, and in an `==` or `!=` test with a `uint` companion parameter, which binds as `xid`. It reports anywhere else: as an ordering key, under `<`, `<=`, `>` or `>=`, inside arithmetic, compared with a constant or a column, as a setter's target or value, or as the column an `IN` subquery's `Select` picks. Inside a subquery's own `Where`, an `==` or `!=` test with a `uint` parameter is read as anywhere else. A `uint` parameter compared with `xmin` reports wherever else the chain uses it, and one compared with a `uint` column that is not `xmin` reports at that column.

A query `Contains` reports as well when:

- its source does not end in a `Select` of exactly one mapped column, such as a `Select` of a record or a parameter, or a chain without `Select`, a `GroupBy`, or a terminal such as `Count()`;
- the subquery reads the outer row, as in `Where(t => t.Id == e.ParentId)` inside `Where(e => ...)`: a correlated subquery is not translated. Join first, or filter on a companion parameter;
- the selected column can be null and the subquery does not filter it with `!= null`. `NOT IN` is NULL for every row once the subquery selects a NULL, where C#'s `!Contains` is true or false. The outer value may be null: write `Select(t => (Guid?)t.Id).Contains(e.ParentId)`, and a null value is not contained, as in C#.

It also fires on a composite, a type such as `Money(decimal Amount, string Currency)` that `[Query]` binds as one parameter per constructor argument and reads from as many columns, or a type with `[Materialize(Factory = ...)]`, which is read from its factory's columns. A companion parameter of such a type is reported at the parameter, and an entity member of one where the chain uses it: the SQL would name one value where there are several.

## Fix

Use the operators of `ZeroAlloc.ORM.Linq`, with `Select` last, and only `Where` and `WhereIf` before a write. Write the query as a raw `[Query]` when it needs SQL the translator does not produce.

## Example

```csharp
// Fires ZAO102 — HAVING is not translated; filter before grouping:
private static IQuery<StatusCount> BusyQuery() =>
    Sql.Table<TaskEntity>()
        .GroupBy(t => t.Status)
        .Where(g => g.Count() > 1)
        .Select(g => new StatusCount(g.Key, g.Count()));
```

```csharp
// Fires ZAO102 — Shuffle is not a ZeroAlloc.ORM.Linq operator:
private static IQuery<TaskSummary> TasksQuery() =>
    Sql.Table<TaskEntity>().Shuffle().Select(t => new TaskSummary(t.Id, t.Title));
```

```csharp
// Fires ZAO102 at e.TaskId — the subquery reads the outer row, a correlated subquery:
private static IQuery<ExecutionLine> OpenTaskExecutionsQuery() =>
    Sql.Table<ExecutionEntity>()
        .Where(e => Sql.Table<TaskEntity>()
            .Where(t => t.Id == e.TaskId && t.Status == WorkStatus.Open)
            .Select(t => t.Id)
            .Contains(e.TaskId))
        .Select(e => new ExecutionLine(e.Id, e.InputTokens));
```

Fix by filtering the subquery on the parent table alone; `Contains` already matches the row:

```csharp
private static IQuery<ExecutionLine> OpenTaskExecutionsQuery() =>
    Sql.Table<ExecutionEntity>()
        .Where(e => Sql.Table<TaskEntity>()
            .Where(t => t.Status == WorkStatus.Open)
            .Select(t => t.Id)
            .Contains(e.TaskId))
        .Select(e => new ExecutionLine(e.Id, e.InputTokens));
```

```csharp
// Fires ZAO102 — ParentId can be null, and a NULL in the subquery makes IN or NOT IN NULL where C# gives true or false:
.Where(e => !Sql.Table<TaskEntity>().Select(t => t.ParentId).Contains(e.TaskId))
```

Fix by filtering the NULLs out in the subquery:

```csharp
.Where(e => !Sql.Table<TaskEntity>().Where(t => t.ParentId != null).Select(t => t.ParentId).Contains(e.TaskId))
```

```csharp
// Fires ZAO102 at OrderBy — "'OrderBy' before 'ExecuteDelete' is not supported in a [LinqCommand] chain":
private static int DeleteQuery() =>
    Sql.Table<TaskEntity>().Where(t => t.Order > 0).OrderBy(t => t.Order).ExecuteDelete();
```

Fix by dropping the operator: a `DELETE` or `UPDATE` applies to every row its `Where` matches, in no order.

```csharp
// Fires ZAO102 at s.TurnCount — the target is converted to int?, so a NULL could reach a NOT NULL column:
.ExecuteUpdate(set => set.SetProperty(s => s.TurnCount, (int?)null))
```

Fix by setting a value of the column's own type, such as `0`, or by making the property and the column nullable.

```csharp
// Fires ZAO102 at Sql.Xmin(s) — xmin is a transaction id, compared only for equality:
Sql.Table<AgentSessionEntity>().OrderBy(s => Sql.Xmin(s)).Select(s => new SessionVersion(s.Id, s.TurnCount, Sql.Xmin(s)))
```

```csharp
// Fires ZAO102 at Sum — PostgreSQL rejects FOR UPDATE with an aggregate:
private static IQuery<long> LockedTotalQuery() =>
    Sql.Table<ExecutionEntity>().ForUpdateSkipLocked().Sum(e => e.InputTokens);
```

Fix by locking the rows in one query, then aggregating them in another inside the same transaction, or
by dropping the lock.
