# ZAO112 — LINQ method return type does not fit the query

**Severity:** Error
**Category:** ZeroAlloc.ORM

## Trigger

Fires when a `[LinqQuery]` method's return type does not fit its companion's `IQuery<TRow>`, or a `[LinqCommand]` method's does not fit its companion's `int`. The supported return types are:

- `Task<List<TRow>>`, `Task<IReadOnlyList<TRow>>` or `Task<IList<TRow>>`, for every row;
- `Task<TRow?>`, for the first row or null. The SQL gets `LIMIT 1`;
- the same with `ValueTask` instead of `Task`;
- `IAsyncEnumerable<TRow>`, to stream the rows;
- after `Count()`, `Task<int>`; after `LongCount()`, `Task<long>`; after `Any()`, `Task<bool>`. Each also as `ValueTask`;
- after `Sum`, `Min`, `Max` or `Average`, `Task<T>` with the type the operator returns, such as `double` for `Average` of an `int` or `long`: `int`, `long`, `double` or `decimal`, a nullable one of those, `DateTime?`, `DateTimeOffset?` or `string?`. `Task<double>` and `Task<decimal>` are supported scalar results for `[Query]` too. Also as `ValueTask`.

A `[LinqCommand]` method returns `Task<int>` or `ValueTask<int>`, the rows affected, or `Task` or `ValueTask`. Any other type fires it, such as `Task<long>` or `Task<bool>`.

A terminal's result of any other type fires it: an enum, a `Guid`, a non-nullable `DateTime` or a non-nullable `string`, for example `Max(t => t.Status)` into `Task<WorkStatus>`.

A tuple companion, which returns a tuple of `IQuery<T>`, needs `Task` or `ValueTask` of a tuple,
optionally nullable, with one element per companion element. Each element fits its own chain the same
way: `List<T>`, `IReadOnlyList<T>`, `IList<T>` or `T?`, or after a terminal the value it gives. The
message names the element that does not fit, such as a non-nullable row, or says that the tuple and
the companion have a different number of elements.

It is reported at the method's return type, or for one tuple element at that element.

## Fix

Return one of the supported types, with the companion's row type, or the type its terminal produces.

## Example

```csharp
// Fires ZAO112 — a single row must be nullable:
[LinqQuery(nameof(FirstQuery))]
public partial Task<TaskSummary> First(CancellationToken ct);
```

Fix:

```csharp
[LinqQuery(nameof(FirstQuery))]
public partial Task<TaskSummary?> First(CancellationToken ct);
```

A tuple element fires it the same way:

```csharp
// Fires ZAO112 at `TaskHead Head` — a row element must be nullable:
[LinqQuery(nameof(WithExecutionsQuery))]
public partial Task<(TaskHead Head, List<ExecutionLine> Executions)> WithExecutions(Guid id, CancellationToken ct);

private static (IQuery<TaskHead>, IQuery<ExecutionLine>) WithExecutionsQuery(Guid id) => (...);
```

Fix by declaring `TaskHead? Head`, which reads `null` when the task does not exist.

```csharp
// Fires ZAO112 — the tuple has 3 elements, the companion 2:
[LinqQuery(nameof(WithExecutionsQuery))]
public partial Task<(TaskHead? Head, List<ExecutionLine> Executions, int Count)> WithExecutions(Guid id, CancellationToken ct);
```

Fix by adding the third chain to the companion, such as
`Sql.Table<ExecutionEntity>().Where(e => e.TaskId == id).Count()`, or by dropping the element.

```csharp
// Fires ZAO112 — a [LinqCommand] returns the rows affected, an int:
[LinqCommand(nameof(DeleteQuery))]
public partial Task<string> Delete(CancellationToken ct);
```

Fix by returning `Task<int>`, or `Task` when the count does not matter.
