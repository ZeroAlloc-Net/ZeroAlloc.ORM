# ZAO100 — Invalid LINQ companion

**Severity:** Error
**Category:** ZeroAlloc.ORM

## Trigger

Fires when the companion a `[LinqQuery]` names cannot be read. The generator never runs the companion; it reads its syntax at build time, so the companion must have a fixed shape:

- it is a method of the same type as the `[LinqQuery]` method, and has no overloads;
- it is `static`;
- its body is one expression, or one `return` statement, running from `Sql.Table<T>()` to the last operator;
- it returns `IQuery<T>`, or a tuple of 2 to 7 `IQuery<T>` for a parent with its children. A tuple
  companion's expression is a tuple literal, `(chain1, chain2, ...)`, with one complete chain per element.

A missing companion is reported at the attribute argument; the other cases at the companion. A tuple
companion whose body is a call, `default` or anything other than a tuple literal fires it too, since
the generator reads each chain from the literal.

A `[LinqCommand]` companion returns `int`, and its one chain ends in `ExecuteDelete()` or
`ExecuteUpdate(...)`. It fires when that chain ends in anything else, such as `Count()`, or when the
companion is a tuple. A `[LinqQuery]` companion whose chain ends in a write fires it too, at the write:
use `[LinqCommand]`.

## Fix

Write the companion as a single static expression. Build optional filters inline, not through locals and `if` branches.

## Example

```csharp
// Fires ZAO100 — the query is built through a local:
private static IQuery<TaskSummary> OpenTasksQuery()
{
    var q = Sql.Table<TaskEntity>();
    return q.Select(t => new TaskSummary(t.Id, t.Title));
}
```

Fix by writing one expression:

```csharp
private static IQuery<TaskSummary> OpenTasksQuery() =>
    Sql.Table<TaskEntity>().Select(t => new TaskSummary(t.Id, t.Title));
```

A tuple companion fires it when its body is not a tuple literal:

```csharp
// Fires ZAO100 — the tuple comes from another method, so there are no chains to read:
private static (IQuery<TaskHead>, IQuery<ExecutionLine>) WithExecutionsQuery(Guid id) => Pair(id);
```

Fix by writing both chains in the literal:

```csharp
private static (IQuery<TaskHead>, IQuery<ExecutionLine>) WithExecutionsQuery(Guid id) =>
    (Sql.Table<TaskEntity>().Where(t => t.Id == id).Select(t => new TaskHead(t.Id, t.Title)),
     Sql.Table<ExecutionEntity>().Where(e => e.TaskId == id).OrderBy(e => e.ExecutedAt)
        .Select(e => new ExecutionLine(e.Id, e.InputTokens)));
```

A `[LinqCommand]` fires it when its chain does not write:

```csharp
// Fires ZAO100 — "its chain must end in ExecuteDelete or ExecuteUpdate":
[LinqCommand(nameof(CountQuery))]
public partial Task<int> Count(CancellationToken ct);

private static IQuery<int> CountQuery() => Sql.Table<TaskEntity>().Count();
```

Fix by ending the chain in the write, or by declaring the method `[LinqQuery]` if it reads:

```csharp
[LinqCommand(nameof(DeleteDoneQuery))]
public partial Task<int> DeleteDone(CancellationToken ct);

private static int DeleteDoneQuery() =>
    Sql.Table<TaskEntity>().Where(t => t.Status == WorkStatus.Done).ExecuteDelete();
```
