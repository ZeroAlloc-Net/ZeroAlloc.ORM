# ZAO100 — Invalid LINQ companion

**Severity:** Error
**Category:** ZeroAlloc.ORM

## Trigger

Fires when the companion a `[LinqQuery]` names cannot be read. The generator never runs the companion; it reads its syntax at build time, so the companion must have a fixed shape:

- it is a method of the same type as the `[LinqQuery]` method, and has no overloads;
- it is `static`;
- its body is one expression, or one `return` statement, running from `Sql.Table<T>()` to the last operator;
- it returns `IQuery<T>`, or a tuple of 2 to 7 `IQuery<T>` for a parent with its children. A tuple
  companion's expression is a tuple literal, `(chain1, chain2, ...)`, with one complete chain per element.

A missing companion is reported at the attribute argument; the other cases at the companion. A tuple
companion whose body is a call, `default` or anything other than a tuple literal fires it too, since
the generator reads each chain from the literal.

## Fix

Write the companion as a single static expression. Build optional filters inline, not through locals and `if` branches.

## Example

```csharp
// Fires ZAO100 — the query is built through a local:
private static IQuery<TaskSummary> OpenTasksQuery()
{
    var q = Sql.Table<TaskEntity>();
    return q.Select(t => new TaskSummary(t.Id, t.Title));
}
```

Fix by writing one expression:

```csharp
private static IQuery<TaskSummary> OpenTasksQuery() =>
    Sql.Table<TaskEntity>().Select(t => new TaskSummary(t.Id, t.Title));
```
