# ZAO069 — Return value parameter on a dialect without procedure return values

**Severity:** Error
**Category:** ZeroAlloc.ORM

## Trigger

Fires on a `[StoredProcedure]` parameter bound as the procedure's `RETURN`
value when the repository declares a dialect other than SQL Server with
[`[Dialect]`](../cookbook/provider-quirks.md#declaring-the-dialect). A
parameter is bound that way in either of two ways:

* by `[Param(Direction = ParameterDirection.ReturnValue)]`, under any name;
* by the `RETURN_VALUE` convention: a parameter whose bound name is exactly
  `RETURN_VALUE`, whose tuple field is `int` or `int?`, and whose `[Param]`
  writes no `Direction`.

Only SQL Server has a procedure `RETURN` value. A PostgreSQL or MySQL
procedure has none, and SQLite has no procedures. The provider never sets the
parameter, so the generated method would throw
`ZeroAllocOrmMaterializationException` after every call. With the dialect
declared, the generator reports it at build time instead, and the repository
is not emitted.

```csharp
[Dialect(SqlDialect.PostgreSql)]
public sealed partial class OrderRepository(IAsyncDbConnection connection)
{
    // ZAO069: PostgreSQL procedures have no RETURN value.
    [StoredProcedure("allocate_order")]
    public partial Task<(int NewOrderId, int Status)> AllocateAsync(
        int newOrderId,
        [Param(Direction = ParameterDirection.ReturnValue)] int status,
        CancellationToken ct);
}
```

## Fix

Return the value through an output parameter. Declare it `OUT`, or `INOUT`,
in the procedure and bind it as one:

```csharp
// CREATE PROCEDURE allocate_order(INOUT new_order_id INT, OUT status INT) ...
[StoredProcedure("allocate_order")]
public partial Task<(int NewOrderId, int Status)> AllocateAsync(
    int newOrderId,
    [Param(Direction = ParameterDirection.Output)] int status,
    CancellationToken ct);
```

For a parameter that binds by the `RETURN_VALUE` convention, write
`[Param(Direction = ParameterDirection.Output)] int RETURN_VALUE`, or
`InputOutput` for an `INOUT` parameter. A written `Direction` wins over the
convention, so the parameter becomes an ordinary output parameter. See
[Return values](../cookbook/stored-procedures.md#return-values) for how
Npgsql names that argument.

If the repository does run on SQL Server, correct the `[Dialect]` attribute
instead.

## Not triggered when

* No dialect is declared, on the repository or the assembly. The generator
  cannot see the provider, and the parameter binds as a return value as
  before.
* The declared dialect is `SqlDialect.SqlServer`.
* The declared value is not a member of `SqlDialect`, which counts as no
  declaration.
