# ZAO116 — SQL placeholder where a value belongs

**Severity:** Error
**Category:** ZeroAlloc.ORM

## Trigger

Fires when a `{name}` or `{col:Name}` placeholder in the SQL of a `[Query]` or `[Command]` method sits where a value belongs. A placeholder is spliced into the SQL text verbatim and is never escaped, so a value there is an injection hole.

The rule is a narrow heuristic on the SQL, not a parser. It flags a placeholder in these positions only:

- right after `=`, `<`, `>`, `<=`, `>=`, `<>` or `!=`, ignoring whitespace;
- right after the keyword `LIKE`;
- right after `IN (`;
- inside a `VALUES (...)` tuple, at nesting depth one, in every row of a multi-row `VALUES`;
- anywhere, for a `{name}` table placeholder only, when the name equals, ignoring case, a parameter name the SQL also writes as `@name`, `:name` or `$name`. A `{col:Name}` placeholder is exempt: a column named like its parameter, as in `WHERE {col:Id} = @id`, is the idiomatic case.

It never fires for identifier positions: after `FROM`, `JOIN`, `UPDATE`, `INTO` or `TABLE`, after a dot as in `t.{col:Id}`, in a column list such as `INSERT INTO {table} ({col:Id}, {col:Name}) VALUES (@id, @name)`, after `SELECT`, or in `ORDER BY`. A column on the left of an operator, as in `WHERE {col:Id} = @id`, is fine, and so is an `INSERT` column list next to `VALUES (@id, @name)`.

The diagnostic is reported at the method's name, once for each distinct placeholder text of the method.

### Known false negatives

Comments between tokens are ignored. The rule does not look further than the positions above. A placeholder deeper in a `VALUES` tuple, as in `VALUES (@a, COALESCE({x}, 1))`, after `BETWEEN` or `AND`, after `,` in an `IN` list, or after `OFFSET` or `LIMIT` is not flagged.

### Known false positives

A column placeholder on the right of an operator and not qualified, as in `a.Id = {col:Id}`, is flagged: the heuristic cannot tell it from a value. Qualify it, as in `a.Id = b.{col:Id}`, which follows a dot and is not flagged. A `{name}` placeholder whose name equals a parameter name is flagged too, even in an identifier position: rename one of them.

## Fix

Use a `@parameter` for values and keep placeholders for table and column names. Pass the value as a method parameter.

The value of a placeholder is configuration, not input: it is spliced into the SQL verbatim and is never escaped or validated, so never pass user input.

## Example

```csharp
// Fires ZAO116 — {table} sits right after the = operator:
public sealed partial class Repo(IAsyncDbConnection connection, string table)
{
    [Query("SELECT COUNT(*) FROM Orders WHERE Status = {table}")]
    public partial Task<int> CountAsync(CancellationToken ct);
}
```

Fix: bind the value as a parameter.

```csharp
public sealed partial class Repo(IAsyncDbConnection connection, string table)
{
    [Query("SELECT COUNT(*) FROM {table} WHERE Status = @status")]
    public partial Task<int> CountAsync(string status, CancellationToken ct);
}
```
