# ZAO067 — Return value parameter must be int

**Severity:** Error
**Category:** ZeroAlloc.ORM

## Trigger

Fires when `[Param(Direction = ParameterDirection.ReturnValue)]` reads a
stored procedure's `RETURN` value into a tuple field that is not `int` or
`int?`.

A SQL Server procedure's `RETURN` value is always an `int`. No other field
type, including `long`, an enum or a value object over an `int`, can hold it.

The `RETURN_VALUE` naming convention is not reported. A tuple field named
`RETURN_VALUE` whose type is not `int` or `int?` is an ordinary output
parameter, as it was in 2.0.0, because only such a field can hold a
`RETURN` value.

## Fix

Declare the tuple field as `int`, or `int?`:

```csharp
// Fires ZAO067: a RETURN value is an int.
[StoredProcedure("dbo.usp_Allocate")]
public partial Task<(OrderRow Row, long Status)> AllocateAsync(
    int customerId,
    [Param(Direction = ParameterDirection.ReturnValue)] long status,
    CancellationToken ct);

// Fix: read it as an int.
[StoredProcedure("dbo.usp_Allocate")]
public partial Task<(OrderRow Row, int Status)> AllocateAsync(
    int customerId,
    [Param(Direction = ParameterDirection.ReturnValue)] int status,
    CancellationToken ct);
```

If the procedure returns the value through an `OUTPUT` parameter instead,
drop the `Direction`; a tuple-matched parameter is an output parameter by
default.
