# ZAO082 — Provider-specific type requires Npgsql

**Severity:** Error
**Category:** ZeroAlloc.ORM

## Trigger

Fires when a `[Query]`, `[Command]` or `[StoredProcedure]` parameter is a PostgreSQL array and the project does not reference Npgsql. It also fires for a row property of that type that a `[Command(Kind = CommandKind.BulkInsert)]` method inserts, such as `Tags` in `record PostRow(int Id, string[] Tags)`. A PostgreSQL array is one of these shapes:

- `T[]`
- `List<T>`
- `IReadOnlyList<T>`

where `T` is `string`, `int`, `long` or `Guid`. `byte[]` is not an array here: it binds as a binary value on every provider.

Only Npgsql can send these values as a PostgreSQL array. The generator checks for Npgsql by looking for the `Npgsql.NpgsqlParameter` type in your compilation; ZeroAlloc.ORM itself never references Npgsql.

The row collection a `BulkInsert` method takes is not a PostgreSQL array, even when it arrives as an `IReadOnlyList<TRow>`, and does not trigger ZAO082 itself.

## Fix

Pick one of:

1. Reference the Npgsql package in the project that declares the repository, if the database is PostgreSQL.
2. Bind the values another way on other databases, for example as one delimited `string` that the SQL splits, such as `STRING_SPLIT(@tags, ',')` on SQL Server.

## Example

```csharp
// Fires ZAO082 when the project does not reference Npgsql:
public sealed partial class PostRepository(IAsyncDbConnection connection)
{
    [Query("SELECT COUNT(*) FROM posts WHERE tags && @tags")]
    public partial Task<int> CountTaggedAsync(string[] tags, CancellationToken ct);
}

// Fix: reference Npgsql.
// <PackageReference Include="Npgsql" Version="..." />
```
