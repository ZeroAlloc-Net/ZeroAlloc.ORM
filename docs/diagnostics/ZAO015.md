# ZAO015 — [Param(DbType)] is rejected by the declared dialect

**Severity:** Error
**Category:** ZeroAlloc.ORM

## Trigger

Fires on a `[Param(DbType = ...)]` override that the provider of the
repository's declared dialect rejects for the type the parameter binds as.
The command would fail at run time, when the provider binds the parameter,
so the generator reports it at compile time instead.

It applies only when the repository declares its dialect with
[`[Dialect]`](../cookbook/provider-quirks.md#declaring-the-dialect), on the
repository or as the assembly default:

```csharp
[Dialect(SqlDialect.SqlServer)]
public sealed partial class OrderRepository(IAsyncDbConnection connection)
{
    // ZAO015: SqlClient cannot send an int as a Guid.
    [Query("SELECT Id, Total FROM Orders WHERE Id = @id")]
    public partial Task<OrderRow?> GetAsync([Param(DbType = DbType.Guid)] int id, CancellationToken ct);
}
```

```text
error ZAO015: [Param(DbType = Guid)] on parameter 'id' of method 'GetAsync' fails at run time:
Microsoft.Data.SqlClient, the provider of the declared SqlServer dialect, rejects DbType Guid
for a value of type 'int'
```

The check covers the parameters of `[Query]`, `[Command]` and
`[StoredProcedure]` methods that send a value: input parameters, and
`[StoredProcedure]` parameters with `Direction = InputOutput`.

A parameter is checked as the primitive it binds as. A value object such as
`OrderId(int Value)` and an enum are checked as their underlying `int`, a
`[StoreAsString]` enum as a `string`, and `int?` as `int`.

## Why it needs a declared dialect

No `DbType` member is rejected by every provider. Microsoft.Data.Sqlite ignores
`DbType`, and MySqlConnector accepts every pair. A check that ran without
knowing the provider would report code that works on some provider, so without
a declared dialect ZAO015 never fires. See
[#243](https://github.com/ZeroAlloc-Net/ZeroAlloc.ORM/issues/243) for the probe that showed this.

## What each dialect rejects

The rejected pairs come from a probe against live servers: every `DbType`
member against each bound type, sending the value with `SELECT @p`. A pair is
rejected only when the provider throws for every value tried. A value the
provider converts or reinterprets counts as accepted, so an accepted pair is
not necessarily a sensible one: Npgsql sends an `int` as `DbType.Date` by
reading it as a day number.

`DbType.Object`, the attribute's default, is never reported. A value outside
the `DbType` enum, such as `(DbType)999`, is rejected by SqlClient and Npgsql
for every type.

### SQLite and MySQL

Nothing is reported. Microsoft.Data.Sqlite ignores `DbType`, including an
undefined value. MySqlConnector accepted every pair. MySql.Data rejects some,
for example a number as `DbType.Date`, but a pair is reported only when both
documented libraries reject it.

The SQL Server, PostgreSQL and SQLite sets are checked against the providers
this repository pins, Microsoft.Data.SqlClient 7.1, Npgsql 10 and
Microsoft.Data.Sqlite 10, by `DialectDbTypeRejectionParityTests` in the
integration suite.

## Fix

Write a `DbType` that fits the parameter's type, or remove the override and
let the provider infer the type from the value:

```csharp
[Query("SELECT Id, Total FROM Orders WHERE Id = @id")]
public partial Task<OrderRow?> GetAsync(int id, CancellationToken ct);
```

If the repository does not run on the declared dialect, correct the
`[Dialect]` attribute instead.

## Not triggered when

* No dialect is declared, on the repository or the assembly.
* The dialect is `SqlDialect.Sqlite` or `SqlDialect.MySql`.
* The parameter is a pure output parameter, a `[StoredProcedure]` parameter
  that a tuple field reads back without `Direction = InputOutput`. It sends no
  value, and Npgsql accepts any `DbType` on one.
* The parameter's type is `DateOnly` or `TimeOnly` and the `DbType` is a
  member of the enum. These types were not probed.
* [ZAO066](ZAO066.md) already reports a `[Param]` member on the parameter.
  Composite, `CancellationToken`, transaction and BulkInsert collection
  parameters take no `DbType`, and ZAO066 reports one written on them.
