# ZAO114 — LINQ companion does not compile

**Severity:** Error
**Category:** ZeroAlloc.ORM

## Trigger

Fires when the translation of a `[LinqQuery]` or `[LinqCommand]` method fails and the companion method has a C# compile error. The message carries the compiler's own id and text, for example `CS1503: Argument 2: cannot convert from 'IReadOnlyList<string>' to 'string[]'`, and the diagnostic is reported at the expression the compiler points to. At most five errors are reported.

A companion that does not compile cannot be read: the compiler marks the calls that fail to bind as invalid, so the translator cannot see the chain. Without this diagnostic the build shows only ZAO102 on the whole chain, which blames the wrong cause, and CS8795 on the partial method. CS8795 makes the compiler skip the errors inside method bodies, so the real error would never show. ZAO114 reports it in their place.

Typical causes are a type mismatch in a projection, a name that does not resolve, and a name that resolves to something else, such as a namespace called `Sql` beside the repository that hides `ZeroAlloc.ORM.Linq.Sql`.

## Fix

Fix the C# error the message names. Once the companion compiles, any remaining translation problem is reported as ZAO102 or one of its neighbours.

## Example

```csharp
internal sealed record SkillTagsRow(string Name, string[] Tags);

// Fires ZAO114 — Tags is an IReadOnlyList<string>, the record takes a string[]:
private static IQuery<SkillTagsRow> SkillTagsQuery(string name) =>
    Sql.Table<Skill>().Where(s => s.Id == name).Select(s => new SkillTagsRow(s.Id, s.Tags));
```

Fix: take the type the property has.

```csharp
internal sealed record SkillTagsRow(string Name, IReadOnlyList<string> Tags);
```
